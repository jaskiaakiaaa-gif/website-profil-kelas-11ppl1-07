# website-profil-kelas-11ppl1-07

C. Misi 1: 
-Fungsi GitHub Issue: Sebagai alat pelacakan (tracking) tugas, fitur, atau masalah dalam proyek.
-Mengapa pekerjaan dicatat sebagai Issue: Agar pembagian tugas jelas, terstruktur, dan setiap anggota mengetahui apa yang harus dikerjakan.   
-Perbedaan Issue dengan Commit:Issue: Catatan rencana tugas atau masalah yang akan dikerjakan.Commit: Rekaman perubahan (kode) nyata yang sudah disimpan ke dalam repository.

Q. Simulasi Masalah
Kasus 1 (Pekerjaan kembar): Seharusnya pembagian tugas dibagi sejak awal menggunakan Assignee di GitHub Issue agar tidak ada anggota yang mengerjakan hal yang sama.

Kasus 2 (Belum ada PR): Tidak, karena kode belum digabung (merge) dan belum direview oleh tim. Selesai tidaknya tugas ditandai dengan adanya Pull Request dan hasil review.

Kasus 3 (Jumlah commit berbeda): Belum tentu. Kualitas kode dan kompleksitas pekerjaan jauh lebih penting daripada sekadar banyaknya jumlah commit.

Kasus 4 (Banyak commit ubah spasi): Dinilai kurang efektif. Kontribusi dinilai dari fungsionalitas dan perubahan substansial pada kode, bukan dari perubahan kosmetik yang kecil.


REFLEKSI TIM
Sebelum menggunakan GitHub Issues: Pekerjaan tim terasa kurang terstruktur, pembagian tugas antartim sering membingungkan, dan sulit melacak siapa yang sedang mengerjakan bagian apa.

Setelah menggunakan GitHub Issues: Alur kerja menjadi jauh lebih jelas, setiap tugas terbagi rapi dengan assignee dan label yang jelas, serta progres proyek bisa dipantau dengan mudah.

Hal yang paling membantu: Fitur Issue, Assignee, dan Pull Request yang membuat kolaborasi antaranggota tim lebih terarah dan terhindar dari duplikasi pekerjaan.

Hal yang masih membingungkan: Penyesuaian menggunakan perintah Git (seperti branching, push, pull, dan merge) jika terjadi konflik kode.

Perbaikan workflow tim: Memastikan setiap anggota membaca Issue dengan teliti, selalu membuat branch baru sesuai fitur sebelum coding, dan disiplin melakukan code review sebelum di-merge.
